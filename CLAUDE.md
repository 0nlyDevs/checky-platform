Key architecture decisions (all reflected in the PRD):

- **Auth:** Better Auth runs in Next.js (email + password, `jwt` plugin, 15-min EdDSA JWTs). The browser gets a token from `/api/auth/token` and calls FastAPI with `Authorization: Bearer`. FastAPI verifies against `/api/auth/jwks` (`app/core/security.py`). Issuer and audience = `BETTER_AUTH_URL` and must match `AUTH_ISSUER` / `AUTH_AUDIENCE` on the API.
- **One Postgres, two schemas:** `better_auth` (Better Auth tables, created by its CLI; not `auth`, which hosted platforms such as Supabase reserve) and `app` (ours, Alembic). User ids in `app` are Better Auth ids (text), no cross-schema FK. `better_auth."user"` is declared read-only in `app/core/models.py` for name joins and excluded from Alembic.
- **No Redis.** Background jobs = `app.job` table claimed with `SELECT … FOR UPDATE SKIP LOCKED` by worker loops inside the API process (`app/workers/queue.py`, `JOB_WORKERS`, default 2). Add a job kind with `@handler("kind")`. Interrupted jobs are requeued on startup.
- **Realtime:** Socket.IO on the API (same port). Handshake requires the JWT; client emits `join` with a workspace id (membership checked). Events: `item.created|updated|deleted`, `comment.created`, `job.progress|done|failed`, `demo.reset`.
- **Generic item model:** `app.item` with `type`, `status`, `tags`, and a JSONB `data` merged on PATCH (new day-one fields need no migration). Claim fields currently in `data`: `ref` (FAN-0142), `first_seen_at` (ISO), `origin` (facebook|whatsapp|tiktok|radio|press|other), `verdict` (confirmed), `verdict_suggested` (AI), `source_count`, `assignee_id`, `demo`.
- **Statuses:** `to_check`, `in_progress`, `verified`, `published`. **Verdicts:** `true`, `misleading`, `false`, `unverifiable`. The AI only suggests; a journalist always confirms.
- **AI gateway** (`app/core/ai.py`): `await complete(messages, tools?, **params)` → `Completion` (content, tool_calls, provider, model, tokens, `.message`); `complete(..., stream=True)` → `Stream` of text deltas with `.completion` set at the end. Plain httpx against OpenAI-compatible `/chat/completions`. Providers follow `LLM_PROVIDERS`, a provider with no key is skipped, and default models live in `PROVIDERS` (override with `LLM_MODEL_*`). Quota-aware (measured 25 Oct: Groq free = 1 000 requests/day but only **8 000 tokens/minute**): each `*_API_KEY` may be a comma list (one per teammate, used in turn); a **429 sets that key aside** for `AI_COOLDOWN` (default 30 s, or the Retry-After) and moves on at once, no retry; 5xx/timeouts are retried `AI_ATTEMPTS` times then set aside; a prompt larger than `LLM_MAX_PROMPT_TOKENS_<PROVIDER>` (Groq 6 000, estimated as JSON chars / 3) skips that provider; other errors (bad key, 400) fall back straight away; a stream only falls back before its first chunk. Every attempt goes to `app.ai_call` (no prompt text). `AI_CACHE=true` caches answers in `app.ai_cache` (survives restarts and Render's ephemeral disk; re-running an analysis returns the same answer). Prompts are kept small: the checker sends each source's best RAG passages (≤ 2 500 chars each, ≤ 14 000 total), `/ask` 4 passages. Tests reset `ai._turn`/`ai._cooldown` per test. `AiUnavailable` → 503 `ai_unavailable`. Tests mock providers with `ai._transport` (httpx.MockTransport) and `ai._sleep`. Tool calls replayed to another provider after a fallback are translated by `ai._replay`: Gemini requires a thought signature on earlier calls (foreign ones get its documented `skip_thought_signature_validator`), the others get `extra_content` removed.
- **Errors** leave the API as `{"error": {"code", "message"}}`. Outsiders get **404** (not 403) on a workspace.

## API (FastAPI, prefix `/api/v1`)

Implemented: `GET /health` (public; database, storage and each AI provider as `up|down|not_configured` with latency; providers checked via their free `/models` list; cached 15 s; `ok` = DB up, nothing configured down, at least one configured AI provider up) · `GET /me` (with memberships) · `POST /workspaces` · `GET /workspaces/{ws}/members` (with names/emails) · `PATCH|DELETE /workspaces/{ws}/members/{user}` (last-admin guarded) · `POST /workspaces/{ws}/invitations` · `POST /invitations/{token}/accept` (single use, 7 days) · items CRUD + filters `GET|POST /workspaces/{ws}/items`, `GET|PATCH|DELETE …/items/{id}` · `GET|POST …/items/{id}/comments` · `GET /workspaces/{ws}/activity?entity_id=` · `GET …/jobs/{id}`, `POST …/jobs/{id}/retry` · `POST /workspaces/{ws}/demo/reset` (admin; seeds 8 claims and 7 attached text sources titled "Démo · … (exemple fictif)", indexed for RAG, so the checker, Vérifier and the card work on a fresh demo; a reset replaces them) · files and sources (M4): `POST …/files/upload-url` (presigned PUT; images, PDF, audio, 25 MB) → browser uploads to Neon → `POST …/files/{id}/complete {item_id?}` creates a source and queues `ingest_file` (SHA-256, EXIF via Pillow, PDF text via pypdf); `GET|POST …/sources` (`{url}` queues `ingest_url`: SSRF-guarded fetch with a browser user agent, trafilatura without tables; `{text}` is ready at once), `GET|DELETE …/sources/{id}`, `GET …/sources/{id}/text`; audio sources are transcribed inside `ingest_file` by Groq Whisper (`app/core/stt.py`, `STT_MODEL` default `whisper-large-v3`, verbose_json segments, retries, logged to `app.ai_call` as `groq-stt`) into `app.transcript` + the source text; `GET …/sources/{id}/transcript`, `POST …/sources/{id}/transcribe {language: fr|mg}` re-runs it; events `source.created|updated|deleted`; attaching to a claim keeps `data.source_count` in sync and logs an item `source` activity · RAG (M8, `app/modules/rag.py`, `app/core/embed.py`): every ready source with text is split (~2 400 chars, 300 overlap; transcripts by segments, keeping start/end) and embedded by `embed_source` (chained after `ingest_file`/`ingest_url` and text sources) into `app.chunk` (pgvector 768, HNSW cosine); embeddings via Gemini `gemini-embedding-2` (OpenAI-compatible endpoint; it omits `index`, results are in order), chosen on 25 Oct after an 18/18 FR/MG/cross-language top-3 test; `POST …/search {query,k,item_id?}` → passages with scores; `POST …/ask` SSE: `citations` (numbered passages) → `delta` → `done`|`error`, answer only from passages, cites [n] (models sometimes write 【n】; the UI handles both), says when sources cannot answer; `scripts/reembed_all.py` rebuilds every vector; tests default to `EMBED_PROVIDER=none` and opt in · agent (M10, `app/modules/agent.py`): `POST …/agent` SSE `step` ({n, tool, input, summary}) → `answer` ({text, citations}) → `done`|`error`; tool loop over `ai.complete(tools=…)`, at most 6 model turns (the last without tools so it must answer); tools `search_sources` (RAG), `fetch_url` (SSRF-guarded, same fetcher as ingest), `find_claims`; add one by writing `async def tool(ctx, **args) -> (summary, result)` and registering it in `TOOLS`; no web search (no free API configured) · **site agent** on the same loop (`agent.tool_loop(ctx, messages, tools, max_steps)`; optional tool arguments accept null for Groq; write tools only *propose*, via `ctx.propose(kind, …)`, returned in `answer.actions`): `POST /public/agent` (`app/modules/guide.py`, no account, 12 per address per 10 min, 4 model turns) takes `{messages (last turns), lang fr|mg, page, tips (tokens from this device)}`, tools `search_verdicts` (cites published verdicts), `list_newsrooms`, `draft_tip` (a `tip` action the visitor edits and sends through `POST /public/tips`), `my_tips`, `open_page` (`navigate` action); `POST /workspaces/{ws}/copilot` (`app/modules/copilot.py`, same body, 4 turns; knows the claim of the page it is asked from) with `desk_overview` (counts, open claims oldest first, claims without sources, public tips, last 12 h), `find_claims`, `search_sources`, `propose_create_claim|attach_link|analysis|status`, `open_claim`; a confirmed proposal runs through `POST /workspaces/{ws}/copilot/act {kind, …}` with the journalist's own rights (the ordinary item, source and analyze routes); it never sets `published` and never touches the verdict · F3 interview to quotes (`app/modules/quotes.py`): `POST …/sources/{id}/quotes` queues `extract_quotes` over the transcript (JSON mode); each quote must be found in the transcript (normalised) and takes the start time of the segment it begins in, otherwise it is dropped; claims keep the time of their `from` passage; stored in `transcript.highlights` and returned by `GET …/transcript`; UI: under the transcript, quotes play from their time and a claim becomes a tracked item in one click · F5 verdict card: `POST …/items/{id}/post {language: fr|mg}` (`app/modules/card.py`, 409 without a confirmed verdict) writes a 2-3 sentence post from the verdict, the analysis reason and the source titles, kept in `item.data.posts[lang]`; the 1080 × 1080 PNG is drawn in the browser (`components/claims/verdict-card.tsx`, fixed DESIGN.md palette, exported with `html-to-image` at 540 × 540 × 2), labels in fr or mg · F1 claim checker: `POST …/items/{id}/analyze` queues `analyze_claim` (`app/modules/checker.py`): the claim + up to 8 ready attached sources (6 000 chars each) go to `ai.complete` in JSON mode; quotes not found verbatim (normalised) in their source are dropped, no backed evidence forces `unverifiable`; result in `item.data.verdict_suggested` + `item.data.analysis` (claims, evidence with stance/quote/source, reason, missing, dropped_quotes, model), activity `analysis`, `item.updated` broadcast · `POST /workspaces/{ws}/ai/complete` (JSON) and `POST …/ai/stream` (SSE: `delta` `{text}` events, then `done` with the full completion, or `error`).

Public, no account (`app/modules/public.py`, prefix `/api/v1/public`): only newsrooms with `workspace.is_public` (admin toggle `PATCH /workspaces/{ws} {is_public}`, also `GET /workspaces/{ws}`; the demo reset turns it on) and only claims at status `published` with a confirmed verdict leave the newsroom. `GET /public/newsrooms` · `GET /public/verdicts?q=&newsroom=` and `/public/verdicts/{id}` (title, verdict, `data.reason` or the analysis reason, the fr post, source titles) · `POST /public/match {text}` "is it already checked?": accent-free word overlap against published verdicts, never an AI verdict · `POST /public/tips {newsroom, text, url?, origin}` creates a `to_check` claim (author `public`, tag `signalement`, `data.public_tip`, `data.tip_token`, next FAN ref), broadcast live to the desk, 5 per address per 10 min (in memory) · `GET /public/tips/{token}` its status and, once published, its verdict. · `POST /public/ask {question}` the public assistant: picks up to 5 published verdicts by word overlap, then `ai.complete` answers only from them with [n] citations (fr or mg); with no match it returns `checked: false` without calling the AI; 10 questions per address per 10 min; on `AiUnavailable` it still returns the matching files. · `POST /public/transcribe?lang=fr|mg` dictation: raw `audio/*` body (≤ 3 MB, about a minute), Groq Whisper with a vocabulary prompt of local names (`VOCABULARY`), nothing stored, 20 per address per 10 min.

Roles: journalist (create, edit own), editor (edit/delete all), admin (members, invites, demo reset). Dependencies `AnyMember`, `Editor`, `Admin` in `app/core/access.py`.

Not yet: conversation history; a seed script with several users (the demo reset covers claims and sources).

## Web app

Public, no account (dossier world, `components/site/public/`): `/verifies` (« Est-ce déjà vérifié ? », the public assistant with clickable [n] citations, + the archive as a list of files), `/verifies/[id]` (a published verdict, its sources, shareable), `/signaler` (tip form; follow-up links remembered in `localStorage` « fanilo:tips »), `/suivi/[token]` (the tip's steps, refreshed every 30 s); `proxy.ts` lets them through signed in or not; Paramètres has the admin toggle « Publier nos verdicts ». The floating assistant (`components/assistant/assistant-widget.tsx`) is the **site agent**, on every page: public and auth pages talk to `/public/agent` (the visitors' guide), inside a workspace (`scope="desk"`, mounted in the app shell) to `/workspaces/{ws}/copilot`. It shows the agent's steps, verdict links for citations, and an action card per proposal (tip: newsroom picker and editable text, then Envoyer/Annuler; desk: Confirmer/Annuler); `navigate` actions open at once. The conversation (last 3 turns sent as history) is kept per scope in `sessionStorage` « fanilo:assistant:* », so it survives the pages the agent opens; in voice mode a pending action is confirmed by saying « oui » (or « eny ») and cancelled by « non ». (Next 16 keeps the previous route hidden after a navigation, so a hidden second widget can sit in the DOM.) Dictation records with `MediaRecorder` and sends to `/public/transcribe` (FR/MG picker); listening stops by itself after ~1.2 s of silence (Web Audio level, 8 s without speech = give up); voice mode sends what was heard at once, reads the answer aloud, then listens again (a hands-free conversation). The voice is ElevenLabs through `POST /public/speak {text, lang}` (`ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL`, default `eleven_flash_v2_5` with `language_code: fr`; Malagasy uses `ELEVENLABS_MODEL_MG` (`eleven_v3`) with no language code, since `mg` is refused; the free plan only allows ElevenLabs' default voices through the API, hence `ELEVENLABS_VOICE_ID` George `JBFqnCBsd6RMkjVDRZzb`; key `fanilo` restricted to text to speech, capped at 8 000 credits; 64 recent answers cached in memory so one answer costs credits once; 20 per address per 10 min; tests blank the key in `conftest.py`); without a key it answers 501 and the browser's `speechSynthesis` reads instead. `proxy.ts` does the optimistic cookie redirect (Next 16 name for middleware).

Data: SWR + `lib/api.ts` (`api()` adds the JWT, caches it until 1 min before expiry). Realtime via `hooks/use-workspace-socket.ts` (refetches after reconnect). `hooks/use-workspace.ts` gives my role and a user-id → name map. Server-side session read: `lib/session.ts` (`'use cache: private'`, behind Suspense in `app/(app)/layout.tsx`).

## Local setup and commands

Prereqs on this machine: Node 26 / npm 12, Python 3.13 via uv, local PostgreSQL 18 (user `postgres`, password in `.env`). Databases: `fanilo` (app) and `fanilo_test` (tests). pgvector 0.8.7 is installed locally (`sudo pacman -S pgvector`) and enabled in `fanilo` and `fanilo_test`; the chunks migration runs `CREATE EXTENSION IF NOT EXISTS vector`.

```bash
npm install                                   # root, installs all workspaces
cd apps/api && uv sync                        # API deps
# first time on a new database (Better Auth writes into the `better_auth` schema, which must exist):
psql "$DATABASE_URL" -c "CREATE SCHEMA IF NOT EXISTS better_auth"
cd apps/web && set -a && . ./.env.local && set +a && npx @better-auth/cli@latest migrate --config lib/auth.ts --yes
cd apps/api && uv run alembic upgrade head    # creates the app schema + tables

# run (two terminals)
cd apps/api && uv run uvicorn app.main:app --reload --port 8000
cd apps/web && npx next dev -p 3000
```

If the web runs on another port, set the same origin everywhere: `BETTER_AUTH_URL` (web) and `AUTH_JWKS_URL`, `AUTH_ISSUER`, `AUTH_AUDIENCE`, `CORS_ORIGINS` (API).

Checks (same as CI):
```bash
cd apps/api && uv run ruff check . && uv run ruff format --check . && uv run pytest -q && uv run alembic check
```

### Gotchas
- If the dev server reloads the page in a loop after a crash, stop it and `rm -rf apps/web/.next` (regenerable cache).
- A session cookie whose session no longer exists used to bounce `/` ↔ `/connexion` forever (proxy.ts trusts the cookie, the layout does not). `getCurrentUser` now redirects to `/api/session/clear`, which deletes the Better Auth cookies and then goes to `/connexion`. Keep that route outside the proxy matcher.
- Don't use `pkill -f next` from a shell whose command line or cwd contains "next"/the web folder: it kills the shell. Kill by port (`ss -ltnp | grep :3000`).
